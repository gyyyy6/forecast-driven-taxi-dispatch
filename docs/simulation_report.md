# 仿真报告：预测驱动的轻量级闭环调度
> 数据：NYC TLC HVFHV 2023-01-01（sample_day），15 分钟 × 263 Taxi Zone
> 硬件：Intel Ultra 5 集显 + 16G RAM ｜ 仿真引擎：SimPy 4.1.2
> 代码：`src/simulation/env.py`、`policy.py`、`scenarios.py`
## 1. 仿真假设与简化
| 项目 | 设定 | 影响 |
| --- | --- | --- |
| 空间 | 每个 Taxi Zone 用质心代表，区内存量视为 0 | 区内行程按 1 分钟计，低估短途 |
| 距离 | 质心 haversine 直线距离 | 低估实际路网里程（约 20–40%） |
| 速度 | 匀速 25 km/h | 无拥堵、无时段差异 |
| 服务时间 | 常数 12 分钟 | 无订单长度差异 |
| 车辆 | 车辆在服务期间不可被再派 | 与服务后预调度存在结构性取舍 |
| 需求到达 | 每个 (时间片, 区域) 按泊松过程生成，均值 = 预测需求 | 只保留强度，丢弃订单级相关性 |
| 超时处理 | ETA > `max_wait_min` 即拒绝（`served=0`） | 真实系统为排队，本文口径偏保守 |
## 2. 规模口径（关键前提）
`n_vehicles` 是**调度单元数**；`demand_scale` 是对需求做泊松 thinning 的比例。
| 口径 | 全天请求 | 200 车服务率 | 全天耗时 |
| --- | --- | --- | --- |
| 真实（scale=1.0） | 630,073 | 1.6% | 23.3 s |
| 对齐（scale=0.02） | 12,510 | 82.2% | 2.5 s |
真实口径下已服务单数（10,153）等于车队运力上限（200 × 1440 / 28.3 ≈ 10,180），
说明**瓶颈是运力而非调度**，任何策略对比在该口径下都无意义。后文全部使用 scale=0.02。
## 3. 两种策略
### Greedy（基线）
on request(zone, now):
idle ← {v | v.free_at ≤ now}
v ← argmin_{v ∈ idle} travel_min(v.zone, zone)
if travel_min(v.zone, zone) > max_wait_min: reject
else: v.free_at ← now + eta + service; deadhead += dist(v.zone, zone)

### Forecast（预测驱动预调度）
每 15 分钟（时间片边界）:
need[z] = predicted_demand[z] × (service + mean_pickup) / 15 # 单 → 车辆数
deficit[z] = need[z] − idle_supply[z]
targets ← {z | deficit[z] ≥ min_demand_gain}，按 deficit 降序
for target in targets[: max_move_ratio × |idle|]:
从"需求/供给比低于目标区"的区域中取最近空闲车
if eta ≤ min(max_wait_min, 15): 移动并计入空驶
（移动期间车辆不可接单）

## 5. Forecast 有效/无效的原因分析
**8 组配对比较仅 1 组为正（n=200, w=30, r=0.10，+0.09pp），其余 7 组为 -0.14 ~ -0.48pp。**
1. **拥堵工况没有可调资源**：100 辆时任意时刻仅约 9 辆空闲，全天仅约 40 次可行预调度（15 分钟到位约束），而服务总量由运力上限锁定（5,425 单），预调度只能改变"服务哪些"、不能改变"服务多少"。
2. **宽裕工况接驾本已很短**：200/300 辆时平均接驾 6.2/4.3 分钟，"空间错配"本不严重，预调度花费 5–10 分钟运力换来的收益是概率性的。
3. **与匹配半径互为替代**：预调度的唯一价值是减少长途接驾，而收紧 `max_wait_min` 用零成本的方式达到了同一效果（w=15 时 8 组比较全部转负），因此预调度的边际价值被挤出。
4. **正收益只出现在"半径宽松 + 最小比例"**：此时系统还有空间可优化，且移动规模小到成本可承受；继续加大比例则单调变差。
## 6. 局限性
1. 需求只用了 **2023-01-01（元旦）**，是跨年夜异常日（00:30 峰值 13,624 单/片），典型工作日需从 `sample_month` 另切；
2. 无实时路况、无司机行为（拒单/绕路）、无排队（超时即拒）、区域粒度过粗（263 区、区间质心距离）；
3. 预调度不重算目标区缺口，同一时间片内一个目标最多接收 1 辆车；
4. "收紧半径提升吞吐"依赖超时即拒的建模口径，真实平台应改为排队 + 动态定价，结论方向可能改变。
